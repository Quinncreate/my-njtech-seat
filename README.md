# 我的占座

个人本地自习助手，桌面双击启动、浏览器管理任务，使用南京工业大学校徽。有完整 Python、JavaScript 和网页源码，独立于旧版闭源程序运行。

当前版本：**v0.5.1**。运行预约、退座和双账号轮换不需要 AI API Key。架构、学校接口、登录方式和运行边界见 [运行原理与方案](ARCHITECTURE.md)。

## 从 GitHub 下载运行（Windows）

仓库：[Quinncreate/my-njtech-seat](https://github.com/Quinncreate/my-njtech-seat)。当前为私有仓库，下载需要仓库访问权限。

1. 安装 Python 3.11 或更新版本。模拟模式无需第三方 Python 包；真实账号通信还需要 Node.js 22+ 和 Chrome 或 Edge。
2. 建议放在 `C:\Projects\workspace\project\my-njtech-seat`，保留 `workspace\project\项目名` 的目录结构；程序将临时文件写入同一工作区的 `tmp\项目名`。
3. 在 PowerShell 中运行：

```powershell
git clone https://github.com/Quinncreate/my-njtech-seat.git C:\Projects\workspace\project\my-njtech-seat
cd C:\Projects\workspace\project\my-njtech-seat
python .\server.py
```

然后访问 [任务管理](http://127.0.0.1:5003/dashboard/tasks)。也可在文件夹中双击 `启动我的占座.pyw`，由隐藏窗口启动并打开浏览器；新电脑需自行为该文件建立桌面快捷方式。

仓库不含本机任务数据库、账号配置、登录会话、调试产物或本地协作记录。首次运行会创建自己的任务数据库，默认进入模拟模式。本地已验证实际预约、退座与两次双账号接力，长期自动轮换仍待验证，详见下方说明。

## 使用

1. 双击桌面带南京工业大学校徽的“我的占座”，直接进入选座新建页。无需保留终端窗口。
2. 首次打开默认是**模拟演示**；模式之后会保留。选择馆室后，直接在座位图双击白色空闲座位，或从列表选择；选中后变为绿色，并同步更新座位下拉框和任务摘要。保存后点击“开始”。
3. 在“学习概览”点击“演示一次轮换”，观察 A 退座、B 接棒，以及 A 的冷却倒计时。这个按钮仅改变演示时间。
4. 暂停会保留座位；点击“结束轮换”会停止接棒并退掉本任务座位，核对成功后显示“已结束”。“切换至账号 A／B”让另一个固定账号接棒同一座位，暂停任务换号后仍保持暂停。重跑会先建立草稿。
5. 关闭网页不退出后台。点击“退出程序”会停止后台；下次启动先核对预约，再恢复原运行任务。

网页地址：http://127.0.0.1:5003/dashboard/tasks

## v0.5.1 · 旧暂停任务不再误拦截

- 开始新任务时，如果阻塞来源只有旧暂停任务，程序会重新查询两个账号。只有双方登录有效、均无预约，且旧任务没有待核对的操作时，才自动结束旧暂停任务并继续启动新任务；保留旧记录和核对事件，不发送退座请求。
- 运行中、等待开始、仍有预约、登录未确认或操作结果待核对的任务继续阻止重复启动。报错会显示具体任务名称、座位、状态和编号，并直接打开对应任务详情。
- 新增 14 项隔离回归，覆盖旧任务未持座、预约已过期、缓存过时、登录失败、未确认操作与真实冲突定位；所有自动验收均使用虚拟账号。

## v0.5.0 · 结束退座与手动换号

- 任务详情上方新增“切换至账号 A／B”，在原来的两个账号之间手动接棒，不改变账号绑定。先检查双方登录、当前持座和保护等待，再让持座账号退座、另一账号立即预约同一位置。65 秒保护未结束时按钮显示剩余秒数并禁用。
- 点击“结束轮换”后先停止轮换，只释放确认属于该任务的座位，不清除其他预约。后台确认任务座位不再由两账号占用后才显示“已结束”；失败显示“重试退座”，不会重新占座或默默重复退座。
- 结束意图及操作前记录会保存，重启先核对结果。旧网页必须刷新并明确确认退座，避免把旧版“保留预约”的确认误用于新行为。
- 暂停仍保留座位；暂停任务手动换号后保持暂停。按计划到达结束时间、退出程序仍沿用停止轮换且保留预约的行为；本次改变的是主动点击“结束轮换”。
- 新增结束退座、手动双向切换、暂停保持、登录失败、超时与重启恢复的离线测试；新按钮的浏览器自动验收在独立模拟库完成。

## 真实账号

2026-10-20 已现场验证两个独立学校账号登录、账号状态、江浦馆室列表及座位坐标查询。在学校标注的“座位预约（测试）”入口，先完成逸夫馆社科图书借阅室（一）159 号的单次预约、退座，再按用户明确授权完成 A→B→A 两次接力；每次持座至少 65 秒，最后退座，重新查询确认两个账号均无预约、159 号恢复空闲。

本地修复了三处实际连接问题：请求头重复导致 JSON 无法解析；选座请求与学校当前座位图使用的 `reserueSeat` 操作不一致；退座已执行但响应报错时被误判为失败。现在选座请求包含与官网一致的操作名称和空验证码参数，退座后读取实际预约确认释放，无法核对则停止接棒，不重复退座。

上述接力测试由 tmp 中的受控工具调用项目 `LiveProvider`，使用已登录的隔离学校会话，非模拟预约；没有加速真实时钟，也没有创建或启动正式测试任务。**正常到期节奏下的任务自动调度、长时间连续运行及现场异常恢复仍待完整验证。** 本轮未触发学校选座验证码，不能据此认为以后不需要验证码。

本次登录图形验证码由开发代理在联调过程中识别；程序内尚未接入自动验证码识别模块。首次登录或学校使会话过期后，仍需在学校页面重新认证原账号。

本机 A、B 已固定为用户指定的两个账号。启动后自动恢复各自的学校会话并核对；学校要求重新认证时，点击“重新登录”，使用原账号。程序会尝试从门户的“座位预约（测试）”入口进入选座页面，随后自动验证，也可点击“验证登录”。运行期间请保留学校浏览器窗口。账号卡片的“更换绑定账号”用于更换登录身份，任务里的“切换至账号 A／B”用于现有双账号接棒。

- 密码由用户输入学校官网；程序不提供密码表单，不读取或迁移旧版账号配置。
- 浏览器登录档案保存在 `%LOCALAPPDATA%\MyNjtechSeat\BrowserProfiles`，使用 Chrome／Edge 自身的本机 Cookie 存储；密码管理器关闭，不保存账号密码。该目录不进入工作区或 Git。
- 账号绑定只保存加盐指纹与尾号标签，登录与固定绑定不符时阻止请求。主动“更换绑定账号”会为该角色创建新档案；旧档案保留，另一角色不变。
- GraphQL 请求头和校验信息只在当前连接内存中使用；重启后从恢复的学校页面重新获取。学校服务端使会话过期时，不能保证免登录，但不会因此更换账号绑定。
- 新连接且没有持座的账号会保守等待 65 秒，覆盖程序启动前可能发生的退座。
- 自动接棒先核对两个账号的登录、持座和冷却。退座确认后立即给另一账号发送选座请求，中间不添加等待。
- 网络超时或操作结果不明确时先重新读取预约，无法确认则要求处理，避免重复退座或盲目重试。
- 学校要求验证码、返回未知预约格式或登录失效时，会停在核对/处理状态；需要在学校网页处理。
- 身份保护核对学校登录请求中的账号与本机固定指纹，不声称从学校个人资料接口验证身份；新电脑首次绑定时仍应确保 A、B 是不同账号。重复预约记录会阻止继续轮换。

**点击“结束轮换”会退掉本任务座位；暂停、到达计划结束时间和退出程序保留当前预约。** 软件不突破学校预约时限，也不能保证两个独立账号间的请求具有原子性：退座到接棒之间仍存在网络失败或被其他人先选走的可能。

电脑关机、休眠、断网期间不能执行轮换。重启恢复会重新核对实际状态；原预约丢失、其他座位冲突或结果不明确时，要求人工处理。

## 环境与源码

- 本机已具备 Python 3.11、Node.js 22 和 Chrome。模拟功能仅使用 Python 标准库。
- 真实账号通信组件需要 Node.js 22+，以及 Chrome 或 Edge，不需要安装 Python 第三方库。
- `启动我的占座.pyw`：隐藏终端启动并打开网页，重复双击复用当前服务。
- `server.py`：仅绑定本机 127.0.0.1:5003，提供网页和任务接口。
- `seat_core.py`：任务状态、冷却记录、轮换流程和 SQLite 持久化。
- `seat_layout.py`：江浦馆室筛选、座位状态与坐标规范化；未知状态不标为空闲。
- `live_provider.py`、`browser_worker.js`、`browser_headers.js`：学校 GraphQL 适配、隔离浏览器会话及请求头规范化。
- `static`：网页和校徽资产；校徽出处见 `static/EMBLEM_SOURCE.md`。
- `tests`：72 项不访问真实账号的 Python 状态机、适配器与座位筛选验证，另含 1 项 Node 本地 HTTP 请求头回归验证。
- `data/tasks.sqlite3`：本机任务、冷却、动态记录和模拟预约，不含密码、API key 或登录会话。请勿运行两份软件操作同一组真实账号。

临时日志、测试数据库、浏览器测试配置和缓存放在 `C:\Projects\workspace\tmp\我的占座`。正式任务数据库在此项目的 `data` 目录，正式登录档案在上文 AppData 目录。

轮换先核对两个账号，再由持座账号退座、确认释放，立即给另一账号发送同一座位的预约请求，随后核对实际结果。它由两次独立学校请求组成，不能保证座位一定接到。
