# 我的占座

个人本地自习助手，桌面双击启动、浏览器管理任务，使用南京工业大学校徽。有完整 Python、JavaScript 和网页源码，独立于旧版闭源程序运行。

## 从 GitHub 下载运行（Windows）

仓库：[Quinncreate/my-njtech-seat](https://github.com/Quinncreate/my-njtech-seat)。当前为私有仓库，下载需要仓库访问权限。

1. 安装 Python 3.11 或更新版本。模拟模式无需第三方 Python 包；真实账号通信还需要 Node.js 22+ 和 Chrome 或 Edge。
2. 建议放在 `C:\Projects\workspace\project\my-njtech-seat`，保留 `workspace\project\项目名` 的目录结构；程序将临时文件写入同一工作区的 `tmp\项目名`。
3. 在 PowerShell 中运行：

```powershell
git clone https://github.com/Quinncreate/my-njtech-seat.git C:\Projects\workspace\project\my-njtech-seat
cd C:\Projects\workspace\project\my-njtech-seat
python .\server.py
```

然后访问 [任务管理](http://127.0.0.1:5003/dashboard/tasks)。也可在文件夹中双击 `启动我的占座.pyw`，由隐藏窗口启动并打开浏览器；新电脑需自行为该文件建立桌面快捷方式。

仓库不含本机任务数据库、账号配置、登录会话、调试产物或本地协作记录。首次运行会创建自己的任务数据库，默认进入模拟模式。真实预约功能仍待现场联调，详见下方说明。

## 使用

1. 双击桌面“我的占座”。无需保留终端窗口。
2. 打开后默认是**模拟演示**。新建任务、选择馆室和座位、保存，然后点击“开始”。
3. 在“系统概览”点击“演示一次轮换”，观察 A 退座、B 接棒，以及 A 的冷却倒计时。这个按钮仅改变演示时间。
4. 任务可以暂停、编辑、恢复、结束或复制重跑。重跑会先建立草稿。
5. 关闭网页不退出后台。点击“退出程序”会停止后台；下次启动先核对预约，再恢复原运行任务。

网页地址：http://127.0.0.1:5003/dashboard/tasks

## v0.2 · 江浦校区与暗色界面

整个工作台、新建页面和表单采用暗色主题，保留南京工业大学校徽。

- 只显示江浦校区逸夫、浦江两馆的馆室，按馆和楼层区分；排除朗读亭、测试场馆和其他校区。两馆均属江浦校区，依据[学校图书馆机构设置](https://lib.njtech.edu.cn/gk/zzjg.htm)。
- 选择馆室后显示空闲数量、空闲座位列表和座位分布图。绿色为空闲，灰色为已占用，黄色为未知或未开放，蓝色为当前选择。
- 可点击或用键盘选择座位、搜索座位号、缩放与滚动查看分布图。图上位置来自学校的座位坐标，不补画未提供的门窗；缺少坐标时改为座位号列表。
- 编辑器打开期间每 20 秒刷新，也可手动刷新。切换馆室立即清空旧选择；刷新后原座位变为不可用会取消选择，读取失败则禁止保存。
- 新任务只允许选择明确空闲的座位，保存时再次查询。编辑或复制原任务可保留原座位；开始前仍核对两个账号的实际预约，学校最终结果决定选座是否成功。
- 模拟模式中的 48 个座位、状态和布局均为虚拟数据，不表示真实馆室的空闲情况。

已核对旧程序只读返回的座位状态、168 个匿名座位坐标，并用回放验证绘图；新版独立登录后的真实查询、选座和轮换仍待现场联调。

## 真实账号

真实接口适配代码已经实现，**尚未完成本校真实登录、选座和连续轮换的现场联调**；当前交付可验证的是模拟流程和浏览器通信组件。不要将模拟测试理解为真实预约成功保证。

结束演示任务后可切换“真实账号”。分别点击 A、B 的“登录”，在弹出的学校官网窗口手动登录**两个不同账号**，进入图书馆选座页面，再返回点击“刷新 / 验证登录”。登录窗口必须保持打开。

- 密码由用户输入学校官网；程序不提供密码表单，不读取或迁移旧版账号配置。
- 登录会话和 GraphQL 校验信息只在当前进程/无痕浏览器上下文内使用；退出后需要重新登录。
- 新连接且没有持座的账号会保守等待 65 秒，覆盖程序启动前可能发生的退座。
- 自动接棒先核对两个账号的登录、持座和冷却。退座确认后立即给另一账号发送选座请求，中间不添加等待。
- 网络超时或操作结果不明确时先重新读取预约，无法确认则要求处理，避免重复退座或盲目重试。
- 学校要求验证码、返回未知预约格式或登录失效时，会停在核对/处理状态；需要在学校网页处理。
- 当前没有从学校账号身份资料自动判定两个登录是否为同一人的功能；请自行确保两个账号不同。重复预约记录会阻止继续轮换。

**暂停、结束、到达任务结束时间，均只停止轮换，保留当前预约。** 软件不突破学校预约时限，也不能保证两个独立账号间的请求具有原子性：退座到接棒之间仍存在网络失败或被其他人先选走的可能。

电脑关机、休眠、断网期间不能执行轮换。重启恢复会重新核对实际状态；原预约丢失、其他座位冲突或结果不明确时，要求人工处理。

## 环境与源码

- 本机已具备 Python 3.11、Node.js 22 和 Chrome。模拟功能仅使用 Python 标准库。
- 真实账号通信组件需要 Node.js 22+，以及 Chrome 或 Edge，不需要安装 Python 第三方库。
- `启动我的占座.pyw`：隐藏终端启动并打开网页，重复双击复用当前服务。
- `server.py`：仅绑定本机 127.0.0.1:5003，提供网页和任务接口。
- `seat_core.py`：任务状态、冷却记录、轮换流程和 SQLite 持久化。
- `seat_layout.py`：江浦馆室筛选、座位状态与坐标规范化；未知状态不标为空闲。
- `live_provider.py`、`browser_worker.js`：学校 GraphQL 适配及隔离浏览器会话。
- `static`：网页和校徽资产；校徽出处见 `static/EMBLEM_SOURCE.md`。
- `tests`：27 项不访问真实账号的状态机、适配器与座位筛选验证。
- `data/tasks.sqlite3`：本机任务、冷却、动态记录和模拟预约，不含密码、API key 或登录会话。请勿运行两份软件操作同一组真实账号。

临时日志、测试数据库、浏览器空白配置和缓存放在 `C:\Projects\workspace\tmp\我的占座`。正式程序的任务数据库只在此项目的 `data` 目录。

运行离线检查：

```powershell
$env:PYTHONPYCACHEPREFIX='C:\Projects\workspace\tmp\我的占座\python-cache'
python -m unittest discover -s 'C:\Projects\workspace\project\我的占座\tests' -v
node 'C:\Projects\workspace\project\我的占座\browser_worker.js' 'C:\Projects\workspace\tmp\我的占座\browser-smoke' --smoke-test
```

浏览器通信检查只打开空白页，验证两个会话隔离，不登录学校或操作预约。
