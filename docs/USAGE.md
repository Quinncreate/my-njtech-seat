# 使用指南（Windows）

本指南适用于 v0.5.1，当前适配南京工业大学江浦校区的逸夫、浦江两馆。软件在自己的电脑上运行，需要电脑保持开机、联网且不休眠。

## 1. 安装环境

- Python 3.11 或更新版本。安装时勾选将 Python 加入 PATH。
- 真实预约还需要 Node.js 22 或更新版本，以及 Chrome 或 Edge。
- 不需要 AI API Key，也不需要额外安装 Python 包或 npm 依赖。

打开 PowerShell，检查安装是否完成：

```powershell
python --version
node --version
```

Python 必须是 3.11+，Node.js 必须是 22+。更改 PATH 后，重新打开 PowerShell。

## 2. 下载并启动

可以在仓库首页选择 **Code → Download ZIP**，解压到普通项目目录；建议保留 `SeatWorkspace\project\my-njtech-seat` 这样的目录层级，程序会把临时文件放在同一工作区的 `tmp` 目录。

安装了 Git 的用户也可以使用：

```powershell
$seatFolder = Join-Path $env:USERPROFILE 'SeatWorkspace\project\my-njtech-seat'
git clone https://github.com/Quinncreate/my-njtech-seat.git "$seatFolder"
Set-Location "$seatFolder"
python .\server.py
```

打开 [本机任务页面](http://127.0.0.1:5003/dashboard/tasks)。地址中的 `127.0.0.1` 指自己的电脑，这不是可供其他人共用的在线预约网站。

日常可以双击项目里的 `启动我的占座.pyw`，程序会隐藏终端并打开网页；已经运行时会复用后台。若双击没有反应，在项目目录运行 `python .\server.py` 查看启动错误。

### 创建自己的桌面快捷方式

1. 在 `启动我的占座.pyw` 上右键，通过“显示更多选项 → 发送到 → 桌面快捷方式”创建入口；不同 Windows 版本的菜单名称可能略有差异。
2. 右键桌面快捷方式 → 属性 → 更改图标，选择项目 `static` 目录中的 `njtech-emblem.ico`。
3. 如 `.pyw` 未关联 Python，可在快捷方式“目标”中填写自己的 `pythonw.exe` 路径，再加上带引号的启动文件路径。

仓库不包含开发者电脑的快捷方式或安装路径，需要在自己的电脑上创建。

## 3. 先体验模拟模式

第一次运行默认进入“模拟演示”，使用虚拟账号和虚拟座位，不会操作真实预约。

1. 新建任务，选择模拟馆室。
2. **双击白色座位**选中，选中后变绿；红色座位不可选，也可以使用座位列表。
3. 保存任务后，在“我的任务”选择它并点击“开始”。保存本身不会开始预约。
4. 在“学习概览”点击“演示一次轮换”，观察 A、B 接棒及冷却。
5. 结束模拟任务后，再切换到真实账号模式。尚未结束的任务可能阻止切换模式。

## 4. 登录自己的两个账号

下载仓库后没有任何预设可用账号，也不会继承其他使用者的登录。**A、B 只是角色名称，首次使用需分别登录两个不同的学校账号。**

1. 在“学习概览”把运行模式切换为“真实账号”。
2. 程序会为 A、B 分别打开独立的学校浏览器窗口。需要定位窗口时，点击对应账号卡片上的“重新登录”或“查看登录”。
3. 在各自的学校官方页面输入账号和密码，自行完成图形验证码或其他认证。
4. 进入图书馆门户的“座位预约”入口；当前适配的入口可能标为“座位预约（测试）”。程序也会尝试自动进入该入口。
5. 回到本机页面，点击“验证登录”，确认 A、B 都显示就绪。等待学校页面加载完成，保持两个学校窗口打开。

之后启动会尝试恢复自己电脑上的这两个会话。学校使登录过期时，重新认证原账号；验证码识别没有内置，不能保证全程无人值守。

“更换绑定账号”会更换该角色的登录身份，需先结束占用该组账号的任务；任务里的“切换至账号 A／B”只让已经登录的两个账号交接座位，含义不同。

## 5. 创建真实任务

1. 点击“新建任务”，选择江浦校区的馆室。
2. 等待实时座位图加载，双击白色空座，确认其变为绿色。地图使用学校返回的座位坐标，未提供的门窗不会补画。
3. 默认任务名称为“自习”，时间按北京时间设为 07:00—22:00；当天已到 22:00 时使用次日。可以自己修改，开始时间已过时点击开始后立即执行。
4. 保存后，在“我的任务”点击“开始”，确认真实预约提示。
5. 查看账号实际预约和任务状态。仅保存为草稿、正在核对、等待开始或等待冷却，都不代表已经持座。

座位图在编辑器打开期间每 20 秒刷新，也可以手动刷新。白色只表示最近查询时可选，最终是否成功以学校结果为准。若座位被占用或状态未知，请刷新后重新选择。

每组账号同时运行一个任务。旧暂停任务如果没有未确认操作，且重新查询证明两个账号都无预约，会在启动新任务时结束旧空记录；仍有真实冲突时，页面会显示并打开对应任务。

## 6. 任务按钮的含义

| 操作 | 对当前预约的影响 |
| --- | --- |
| 暂停 | 停止自动接棒，保留座位 |
| 恢复 | 先查询实际预约，再恢复执行 |
| 切换至账号 A／B | 满足保护条件后，当前账号退座，另一个账号预约同一位置；原任务暂停时切换后仍暂停 |
| 结束轮换 | 停止接棒并退掉匹配本任务的座位，核实后才显示已结束 |
| 到达计划结束时间 | 停止自动轮换，保留当前预约，仍受学校到期规则限制 |
| 退出程序 | 关闭后台并保留现有预约；下次启动先核对再处理任务 |

关闭管理网页不会退出后台。电脑关机、休眠、断网或退出后台期间无法接棒。

## 7. 常见问题

**不需要 AI，为什么还要浏览器？**

程序使用学校浏览器中已经认证的会话访问预约接口。Python 负责调度，Node.js 负责浏览器连接；账号认证仍由学校系统完成。

**为什么显示冷却？**

程序设置了 65 秒保护等待，新恢复登录且没有预约时也会保守等待。它是当前程序的保护值，不是对学校强制规则的说明。等待期间不要反复新建任务。

**切换后座位一定还在吗？**

不能保证。退座与另一账号预约是两次独立请求，网络故障或其他人先选座都可能导致接棒失败；程序会核对结果，无法确认时停止并提示处理。

**出现“需要处理”“重试退座”怎么办？**

先检查学校窗口是否登录有效，完成验证后再查看学校实际预约。操作结果未知时不要同时在旧程序或另一个实例中反复预约／退座；需要结束时，核对后点击“重试退座”。

**启动提示 5003 端口占用怎么办？**

先检查是否已经运行本项目，尝试打开本机任务页面；不要同时启动两份程序操作同一组账号。若占用端口的是其他软件，先处理其端口冲突。

**在哪里反馈问题？**

使用仓库 Issues，提供版本、已遮盖身份信息的错误描述和复现步骤。不要提交账号密码、Cookie、浏览器登录档案、任务数据库或原始网络抓包。详情见 [本地数据与隐私](../PRIVACY.md)。

## 8. 更新程序

先结束需要释放的任务，再通过页面退出后台，然后更新源码或重新下载。保留自己电脑上的任务库和登录档案，普通更新无需将它们上传到 GitHub；更新后启动并核对学校实际预约。

本软件目前为源码运行方式，不提供打包安装器。完整的长期轮换和现场异常恢复仍待验证。
